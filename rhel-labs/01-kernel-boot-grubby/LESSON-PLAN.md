## Опорные вопросы по ходу

Задавайте до того, как ученик выполнит команду, — пусть сначала предскажет результат.

1. Перед 2.1: «Что покажет `/proc/cmdline` сразу после команды grubby?»
2. Перед 2.3: «Что будет, если выполнить `--args` с тем же ключом и другим
   значением: два значения или одно?»
3. Перед 3.1: «Попадёт ли параметр в `/etc/kernel/cmdline`?»
4. Перед 4.4: «Какой индекс у самого нового ядра?» Ответ «0» на этом стенде неверен —
   это главный наглядный момент занятия.
5. После 4.5: «Подойдёт ли `grub2-reboot` для экзаменационного задания? Почему нет?»

## Типичные ошибки

| Ошибка | Как проявляется | Что показать |
|---|---|---|
| Не перезагрузился | параметр есть в `grubby --info`, нет в `/proc/cmdline` | `./run.sh`, блок «Нужна ли перезагрузка» |
| Правил одну запись вместо всех | после перезагрузки параметра нет | `broken/scenario-01` |
| Выбрал ядро по индексу наугад | грузится не то ядро | `broken/scenario-02` |
| Опечатка в `--remove-args` | код 0, параметр на месте | вывод из 2.3 |
| `sudo cat /boot/loader/entries/*.conf` под обычным пользователем | `No such file or directory` | работать через `sudo -i` |
| Редактирует файлы записей руками | работает, но это не метод из документации | разделы 4.3–4.4 документации RHEL 10 |

## Критерии «тема усвоена»

- Называет по памяти обе пары команд: `--update-kernel=ALL --args` / `--remove-args`
  и `--default-kernel` / `--set-default`.
- После любой правки сам, без напоминания, проверяет запись, перезагружается и
  смотрит `/proc/cmdline` или `uname -r`.
- Объясняет, чем `ALL` отличается от одной записи для ядер, которые поставят позже.
- Задаёт ядро по умолчанию путём и объясняет, почему не индексом.
- Выполняет три задания из `tasks/` примерно за 20 минут суммарно.
