# 02 — Разовая правка параметра в меню GRUB

## Цель экзамена
EX200 (RHEL 10), раздел *Operate running systems*:
**Interrupt the boot process in order to gain access to a system**. Эта же механика —
основа задания 01: правка строки `linux` в меню.

## Задача
Не трогая записи загрузчика:

1. Прервите загрузку, откройте редактор записи по умолчанию (`e`) и допишите в конец
   строки `linux` параметр `systemd.log_level=debug`.
2. Загрузитесь с этой правкой (`Ctrl+x`).
3. Докажите на загруженной системе, что параметр применился к текущей загрузке, но не
   попал в постоянную конфигурацию.
4. Перезагрузитесь ещё раз (уже без правки) и покажите, что параметра больше нет.

## Проверка
```bash
# после загрузки с правкой
cat /proc/cmdline | tr ' ' '\n' | grep systemd.log_level
grubby --info=DEFAULT | grep -o 'systemd.log_level=debug' || echo "в записи нет"

# после обычной перезагрузки
cat /proc/cmdline | tr ' ' '\n' | grep systemd.log_level || echo "в /proc/cmdline нет"
```

## Ожидаемый результат
После загрузки с правкой:
```
systemd.log_level=debug
в записи нет
```
После обычной перезагрузки:
```
в /proc/cmdline нет
```
Правка в меню живёт одну загрузку: в `/proc/cmdline` она есть, в `grubby --info` — нет,
и после перезагрузки исчезает. Это противоположность `grubby --args` из лабы 01, где
параметр остаётся в записи. `systemd.log_level=debug` выбран как безвредный и заметный:
он лишь делает журнал подробнее, читает его systemd (`man 7 kernel-command-line`).
