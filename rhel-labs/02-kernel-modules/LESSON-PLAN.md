## Типичные ошибки

| Ошибка | Как проявляется | Что показать |
|---|---|---|
| Проверяет свой файл, а не итог | параметр «есть», а не действует | `broken/scenario-01`, `modprobe --show-depends` |
| Меняет параметр при загруженном модуле | изменений нет, ошибок тоже | вывод из 2.2 |
| Считает `blacklist` полным запретом | `modprobe` модуль загружает | вывод из 4.1 |
| Смотрит только на `active` у службы | модуль не загружен, служба «в порядке» | `broken/scenario-02`, журнал службы |
| Файл в `modules-load.d` без расширения `.conf` | служба файл не читает | `man modules-load.d` |
| Кладёт файл в `/run/modules-load.d` | на стенде служба падает с `Permission denied` | SELinux: файл получает метку `var_run_t`, служба читать его не может |
| Делает `numdummies=2` постоянным (файл в `/etc/modprobe.d`) | стенд после перезагрузки недоступен почти пять минут | README 3.3: `systemd-analyze blame`, журнал `cloud-init-local` |

Строка про `/run/modules-load.d` — наблюдение со стенда: при подготовке материалов
файл там приводил к `Failed to open ...: Permission denied` и к состоянию `failed` у
службы, в журнале аудита — отказ `{ read }` для `systemd_modules_load_t`. В
методичку для ученика это не вошло. С `/run/modprobe.d` такой проблемы нет.

## Чего на стенде делать нельзя

- Не пересобирать initramfs (`dracut -f`): у стенда нет консоли, ошибка в образе
  оставит машину без загрузки. В методичке эти команды приведены по документации и
  помечены как невыполнявшиеся.
- Не запрещать и не выгружать `xfs`, `nvme`, `nvme_core`, `ena`: это диск и сеть
  стенда.
- Не оставлять `modprobe.blacklist=` в записях загрузчика после 4.5.
- Не делать интерфейсы `dummy` постоянными: если ученик перенёс `options dummy
  numdummies=…` в `/etc/modprobe.d` и перезагрузился, стенд вернётся сам минут через
  пять. После входа обнулите файл и перезагрузите ещё раз.

## Критерии «тема усвоена»

- По памяти называет пары: `modprobe` / `modprobe -r`, `/etc/modules-load.d` /
  `/etc/modprobe.d`, `blacklist` / `install ... /bin/false`.
- После правки `modprobe.d` сам смотрит `modprobe -c` или `--show-depends`.
- Объясняет, почему `modprobe dummy` даёт ноль интерфейсов на RHEL 10 и зачем
  системе эта настройка.
- После постоянной настройки сам перезагружается и проверяет `lsmod` и журнал.
- Выполняет три задания из `tasks/` примерно за 20 минут суммарно.
